# Parity sweep 2: what Penryn still lacks from Minecraft 26.3 on real servers

Second audit (2026-11-24), after the first one (docs/parity-sweep.md). Nine read-only audits (clientbound packets, serverbound packets, configuration, entities, world, inventory, chat and text, packs and fonts, gameplay) compared Penryn's sources with the 26.3 client jar. Every finding with priority 5 or more was then checked by a second agent that tried to refute it; all 85 held (some were re-rated). Priority 10 is the most noticeable on a server; effort is a rough size. Items under "Lower priority" were not independently verified.

## Done since the first sweep

## Confirmed gaps, most noticeable first

- **Right-click with a non-block item while aiming at a block never sends UseItem (water bucket, snowball, ender pearl, egg, fishing rod, splash potion, wind charge, spawn eggs on air-use...)** (serverbound, priority 9, small) — In the right-click path Penryn sends UseItemOn, then computes block_used = (use_duration(held).is_none() && !books::used_in_air(held)) || interactive(block name). use_duration only knows foods, potion, bow, crossbow, shield, trident, spyglass, goat horn and brush, and used_in_air only knows the two books. For every other item (bucket, snowball, egg, ender_pearl, fishing_rod, splash/lingering potion, wind_charge, experience_bottle, firework in air, ender_eye, lead, bone meal on nothing...) block_used is true whenever a block is under the crosshair, so the code only swings (S_PUNCH) and never sends S_USE_ITEM (67). Vanilla's Minecraft.startUseItem sends UseItem whenever useItemOn returns PASS, and Item.useOn is PASS for all of these; the server never throws or places for them from UseItemOn alone. The decision is a name-list heuristic instead of the real result, so it also breaks for custom (CraftEngine/ModelEngine/plugin) items that carry a use effect. *Player sees:* Holding a water or lava bucket and clicking the ground does nothing (it only works aimed at air or water). Snowballs, eggs, ender pearls, splash potions, xp bottles and wind charges can only be thrown when no block is within 4.5 blocks of the crosshair; a fishing rod cannot be cast at the ground or a wall. On a typical survival or PvP server this is hit constantly. *Where:* src/play.rs tick, the 'Using an item' block after self.right_down (about lines 1905-1935): block_used, use_duration (line 73), interactive (line 93); src/books.rs used_in_air (line 103); src/client.rs use_item (line 1344), place (line 1273)
- **Invisible / marker armor-stand holograms: name tag hidden, and tag height wrong** (entities, priority 9, small) — entities.rs draw() only emits a name tag inside `if !invisible && e.death_time == 0`. Vanilla ArmorStandRenderer overrides shouldShowName to just isCustomNameVisible, so an invisible stand still shows its name. EntityTable::dims() has no armor_stand case (no string 'armor_stand' anywhere in src/). Penryn uses the 0.5x1.975 type box for tag height, pick box and rider seat. Vanilla ArmorStand flags are entity data index 15 (byte): 1 small, 4 show arms, 8 no baseplate, 16 marker. Marker stands have a zero box, small ones are half size. *Player sees:* Every hologram built from invisible armor stands (DecentHolograms, HolographicDisplays, TAB, shop and crate labels, 'sit' plugins) shows no text at all. Visible small or marker stands would float the text about 2 blocks too high. Marker stands also block clicks on what is behind them, because pick() hits their 1.975 tall box, so right-click goes to the entity instead of the block. *Where:* src/entities.rs EntityTable::draw (name tag block, ~line 1075) and EntityTable::dims (~line 662), EntityTable::pick (~line 1184); src/riding.rs passenger_attachment (default uses dims().1)
- **UseItem is never sent when the crosshair is on a block (water bucket, ender pearl, snowball, egg, splash potion, fishing rod, firework, armor equip, boats)** (gameplay, priority 9, medium) — Right click with a block under the crosshair sends only ServerboundUseItemOn. The follow-up ServerboundUseItem that vanilla's Minecraft.startUseItem sends when useItemOn returns PASS is skipped, because the code treats any item without a use_duration as consumed by the block. Vanilla server-side useOn for these items returns PASS and does nothing. *Player sees:* Placing water or lava from a bucket onto a block face does nothing. Pearls, snowballs, eggs and splash potions cannot be thrown at a wall or the ground. A fishing rod cannot be cast or reeled in while aiming at a block. Armor cannot be equipped by right click and boats cannot be placed on land. Most of these only work when aiming at open air. *Where:* src/play.rs tick(): `block_used = (usable.is_none() && !crate::books::used_in_air(&held_name)) || interactive(&name)`; `use_duration()`, `interactive()`; src/books.rs used_in_air (only writable_book and written_book); src/client.rs Game::place and Game::use_item
- **Block-breaking speed ignores Efficiency, Haste, Mining Fatigue, Conduit Power and the server's mining attributes; tools are matched by item name only** (serverbound, priority 8, medium) — dig_speed() computes per-tick progress from the block hardness, a name-based tool_of() (suffix _pickaxe/_axe/... and a material prefix), a shears/cobweb special case, water /5 and air /5. It reads no enchantments (efficiency), no mob effects (haste, mining_fatigue, conduit_power), no attributes (block_break_speed, mining_efficiency, submerged_mining_speed; those names appear only in tooltip.rs) and not the item's own tool component (custom tools with custom_model_data or an item_model). The client decides itself when to send STOP_DESTROY_BLOCK (progress >= 1.0, play.rs dig_tick). *Player sees:* Efficiency and Haste tools break blocks at base speed, so they feel sluggish next to the real client; on servers with RPG mining attributes, custom tools or mining fatigue the break time is wrong in both directions. When the client is too fast (mining fatigue, a server-lowered block_break_speed, a slower custom tool) STOP is sent before the server's own progress is done, the server rejects it and the block reappears (ghost block and re-dig). *Where:* src/play.rs dig_speed (about line 2062), tool_of (line 102), dig_tick (line 1990ff); src/effects.rs (no haste/fatigue hook in movement()); no attribute read for block_break_speed
- **text_display entities are not drawn** (entities, priority 8, medium) — display.rs kinds() only finds block_display and item_display; text_display (entity type 135 in entities.bin) has no draw path. entity_data() reads the text COMPONENT (serializer 5) with nbt::skip_root and discards it, and does not keep line width (idx 24), background ARGB (25), text opacity (26) or the style flags byte (27: shadow 1, see-through 2, default background 4, alignment 8/16). Defined indices: Display.TextDisplay first index 23 with 5 defines. *Player sees:* All modern holograms and floating labels are invisible: FancyHolograms, DecentHolograms 3, TAB, leaderboards, NPC name labels, and ModelEngine/MythicMobs name tags and health bars (ModelEngine R4.2.0 NameTagImpl and NameTagRendererImpl use TextDisplay). Nothing replaces them. *Where:* src/display.rs (draw, kinds), src/client.rs entity_data kind 5 (skip_root), src/entities.rs name_tags (reuse the glyph/background quad code)
- **Block and pack textures stay frozen on their first animation frame** (world, priority 8, large) — tools/make_assets.py first_frame() keeps only .mcmeta frames[0], tile_of() scales it to one 16x16 atlas tile, and nothing in the renderer swaps tiles over time. There is no frametime, interpolate or per-frame handling. Water and lava still textures are baked as one frame as well (texture('block/water_still'), texture('block/lava_still')). *Player sees:* Water and lava never ripple. Nether portals, fire, magma, sea lanterns, prismarine, command blocks, kelp, sculk, conduits and every animated texture a resource pack adds (CraftEngine custom blocks, mc.kyttuslab.org pack) are static pictures. This is visible within a second on any server and is the most obvious difference from vanilla. *Where:* tools/make_assets.py first_frame() (~line 402), tile_of() (~534), texture() (~1333), atlas build ~1838-1866; src/mesher.rs fluid quads; src/render.rs terrain draw; README line ~196 admits it
- **Fluids: no flow levels, no flowing texture, waterlogged blocks and seagrass/kelp draw no water** (world, priority 8, large) — src/mesher.rs draws a fluid cell as a box whose top is fixed at 1.0 (fluid above) or 0.875, with only water_uv and lava_uv (the still textures). It ignores the 'level' and 'falling' properties and has no sloped corner heights (FluidRenderer corner heights) and no flow-direction rotation. It never uses water_flow, lava_flow or water_overlay. Only kind WATER (water, bubble_column) and LAVA draw fluid. Blocks with the HAS_FLUID flag (waterlogged stairs, slabs, fences, trapdoors, seagrass, tall_seagrass, kelp, coral, sea pickles) get a plant or block model and no water in their cell. Source top is 0.875 where vanilla uses 8/9. *Player sees:* Rivers, waterfalls, lava flows and water streams are flat full-height slabs that step instead of sloping. Ocean floors with seagrass or kelp have holes in the water surface and missing water faces. Waterlogged stairs and slabs in builds look dry from outside. Lava flows from a generator look like stacked cubes. *Where:* src/mesher.rs mesh() fluid branch (~lines 196-230); src/blocks.rs HAS_FLUID, has_fluid() (only used by physics, boat, particles, special); tools/make_assets.py kind_of() line 671 and flags at line 1547
- **Block entities with an entity renderer are invisible: shulker boxes, banners, skulls and player heads, decorated pots, conduits, end portal and gateway** (world, priority 8, large) — In 26.3 the block models for these are particle-only (jar models/block/shulker_box.json, banner.json, skull.json, decorated_pot.json, conduit.json, end_portal.json, end_gateway.json contain only a particle texture). make_assets bake_model emits no quads for them, and Penryn has no renderer for them. Only chests (chest_quads, CHEST_TEX) and sign text (signs.rs) are drawn. Beds, bells (without the bell body), enchanting table (without the book), beacon (without the beam) and spawners (without the mob) have partial block models. Banner, skull, shulker, bell, conduit, decorated_pot and beacon entity textures are listed in ENTITY_TEX_SKIP. *Player sees:* Placed shulker boxes are an invisible block with a collision. Banners are missing, which is common as server decoration and in spawn areas. Decorative player heads and mob heads (HeadDatabase/CMI heads, trophies) are missing. Decorated pots, conduits and the End portal (a hole you see through) are missing. Bells have no bell. Enchanting tables have no floating book. The beacon has no beam. *Where:* src/signs.rs BlockEntities (keeps only signs); src/client.rs C_BLOCK_ENTITY_DATA handler (~line 651); tools/make_assets.py bake_state/bake_model, ENTITY_TEX_SKIP (~2923), chest_quads (~1383); README ~213
- **High-resolution pack textures are nearest-sampled down to 16x16 tiles** (world, priority 8, large) — make_assets TILE = 16 and tile_of() picks one pixel per 16x16 cell with no averaging. The atlas is a fixed 64x16-px-tile layout, so a 32x, 64x or 256x block texture from a server pack loses its detail and aliases. Custom models with large UV areas (CraftEngine custom blocks) also lose it. Only chest entity textures use big_texture. *Player sees:* On mc.kyttuslab.org or any HD pack server the block textures look like noisy 16x versions. Fine detail, text and normal-looking art in pack blocks is destroyed. *Where:* tools/make_assets.py tile_of() lines 534-544, texture() ~1333, atlas ~1838-1866
- **Container titles, item names and lore drop bold, italic, underline, strikethrough, obfuscation and the font key (GUI plugin glyph titles)** (inventory, priority 8, medium) — nbt::text()/text_of() (the reader for network-NBT components) only understands text, translate, fallback, with, extra and color. It ignores font, bold, italic, underlined, strikethrough, obfuscated and shadow_color. Container titles (client.rs C_OPEN_SCREEN), custom_name/item_name/lore (tooltip.rs), books and others go through it. Only the chat path (text.rs Style, with font_index/set_fonts and the 0xF800+id private code the GUI font reads) is complete, but titles and tooltips never reach it. So a title such as a negative-space-font shift followed by a  glyph from a pack font is drawn with the default font in dark grey, not with the bitmap background glyph. The GUI-plugin technique (ItemsAdder, Nexo, Oraxen, CraftEngine custom GUI backgrounds) does not work. The title is also always drawn at a fixed LABEL colour via text_plain, with no per-component colour override or shadow. *Player sees:* Custom-GUI servers show the plain chest or hopper with a '?' or boxed glyph where the custom background and title art should be. Lore and item names lose bold and italic, and item names/lore using font glyphs (icon characters in lore, rank badges) show as wrong characters. *Where:* src/nbt.rs text_in/text_of (~lines 118-232) and colour_code; src/client.rs C_OPEN_SCREEN (title = nbt::text); src/screens.rs draw_window (gui.text_plain(&win.title...)); src/tooltip.rs lines 586-591 (CUSTOM_NAME, ITEM_NAME, LORE); compare src/text.rs Style.font/bold/italic and gui.rs glyphs_at
- **Name tags of invisible armor stands (holograms) are never drawn** (chat, priority 8, small) — entities.rs only draws a name tag when `!invisible` (flag 0x20 of data 0). Vanilla ArmorStandRenderer overrides shouldShowName to just isCustomNameVisible(), so an invisible armor stand with a visible custom name still shows it. Only LivingEntityRenderer hides names of invisible mobs and players. *Player sees:* Every hologram made from an invisible (usually marker) armor stand, the classic way HolographicDisplays, DecentHolograms, shop/NPC labels and ModelEngine/plugin name labels are built, is simply missing. Spawn, lobby, leaderboards and NPC titles look empty. *Where:* src/entities.rs draw loop ~line 958 (`if !invisible && e.death_time == 0`), name from e.custom_name / e.d(3); custom name read in src/client.rs ~1558
- **Custom and high-resolution textures are squashed to 16x16 tiles** (packs, priority 8, large) — Every block, item and model texture goes through texture() -> tile_of(), which nearest-scales the whole PNG to a 16x16 tile in a fixed 64-tiles-per-row atlas. A pack's HD copy of a vanilla texture is also scale_down()'d to the vanilla size in Assets.image(). Custom-namespace textures (ModelEngine bone textures, CraftEngine/Nexo/ItemsAdder models, 32x/64x/128x/256x skins of custom blocks and items) have no vanilla twin, so they get squashed straight to 16x16 and lose almost all detail. *Player sees:* ModelEngine mobs, custom furniture, custom blocks and custom item icons come out as blocky, noisy, aliased blobs. This affects essentially every server that uses a model plugin or an HD resource pack. *Where:* tools/make_assets.py: texture(), tile_of(), Assets.image(), scale_down(), atlas layout (~lines 1330-1360, 1835-1860); src/render.rs atlas upload (per-16px-tile mipmaps)
- **Animated textures never animate (water, lava, fire, portal and pack flipbooks)** (packs, priority 8, large) — first_frame() bakes only frames[0] of an .mcmeta animation. There is no frame strip in the atlas and no runtime stepping: no frametime, interpolate or frames order, and no TexSubImage call anywhere in src/. Water, lava, fire, nether portal, sea lantern, magma, prismarine, kelp, command blocks, and every animated pack texture (animated custom blocks, items, GUI) stay on frame 0. *Player sees:* Water and lava are frozen, fire and portals are static pictures, and animated pack blocks and items do not move. *Where:* tools/make_assets.py first_frame() (~402), Assets.image(); src/render.rs (no animation tick); src/blocks.rs water_still/lava_still rects
- **Text display entities are never drawn (holograms, ModelEngine/CMI name tags)** (clientbound, priority 7, medium) — SET_ENTITY_DATA kind 5 (Component) is skipped with nbt::skip_root, so a text_display's text (index 23 in Display.TextDisplay), line width, background and opacity are never stored, and display.rs::kinds only knows block_display and item_display. The file header says 'Text displays are not drawn yet'. *Player sees:* Every hologram made with FancyHolograms, DecentHolograms, CMI holograms, or the text-display name tags and health bars many ModelEngine/MythicMobs setups use is invisible. Floating shop, rank and NPC labels are missing on a real server. *Where:* src/client.rs entity_data (case 5 => nbt::skip_root), src/display.rs (kinds(), header comment), src/entities.rs name-tag drawing could be reused
- **Entities with no renderer or spawn data: falling blocks, primed TNT, end crystals, paintings, experience orbs** (clientbound, priority 7, large) — C_ADD_ENTITY reads the final `data` VarInt only for item frames (SPAWN_DATA). The block state of falling_block, the direction of paintings and leash knots, and the owner of projectiles are dropped. No code in src or make_assets names falling_block, tnt, end_crystal, experience_orb or painting entities (painting appears only for registry reading), and PAINTING_VARIANT (data kind 34) is parsed as a plain varint and not used. *Player sees:* Sand, gravel and anvils that fall, TNT cannons and block props made from falling_block entities are invisible. Paintings on walls do not appear. Experience orbs and end crystals do not show. *Where:* src/client.rs C_ADD_ENTITY (about line 889) and entity_data (kind 34); src/entities.rs type list from entities.bin; tools/make_assets.py make_entities
- **Off hand is never used (every use packet sends hand 0): shield, off-hand torches, food, totem-style items** (serverbound, priority 7, medium) — S_USE_ITEM_ON writes varint(0) for the hand, S_USE_ITEM writes varint(0), S_INTERACT writes varint(0). There is no off-hand pass: vanilla's startUseItem loops over MAIN_HAND then OFF_HAND and tries the other hand when the main hand returns PASS or is empty. Penryn only reads the main-hand item name (held_name) for use_duration, so a shield or food in the off hand cannot start a use, and a torch in the off hand cannot be placed while a pickaxe is in the main hand. Only the swap packet (PlayerAction 7) exists. *Player sees:* Sword plus shield (PvP, the common case) cannot block, because right-click with a sword in the main hand does nothing. Off-hand torch placement, off-hand food, off-hand fireworks/crossbow, and an off-hand item that the server expects to be used all do nothing; attacks and entity interaction on servers that rely on off-hand actions fail. *Where:* src/client.rs place/use_item/interact (hand literals), src/play.rs right-click block (lines 1905-1935) and use_duration; inventory slot 45 is the off hand (client.rs line 77)
- **Held and worn items of other entities drop their component patch (custom models and custom armour)** (entities, priority 7, medium) — ClientboundSetEquipment is parsed with client.rs slot(), which returns only (item, count) and throws away the component patch. EntityTable::held_item uses cx.icons[item] (the vanilla icon of the registry item), and mobs.rs equip() picks armour layers from the registry item's table (item_equip) not from the stack's item_model, custom_model_data, profile, dyed_color or equippable.asset_id. Non-armour head items (blocks, pumpkins, player heads, paper with a custom model) are never drawn on the head (README: 'no heads or pumpkins worn'). *Player sees:* Other players holding CraftEngine, Nexo, ItemsAdder or ModelEngine-style custom items show the plain base item (a stick, paper, a plain sword) instead of the custom model.
