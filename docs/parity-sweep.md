# Parity sweep: what Penryn still lacks from Minecraft 26.3

Found by six read-only audits that compared Penryn's sources with the 26.3 client jar (2026-11-23). Each item says what is missing, what a player would notice, and a rough effort. Priority 10 is the most noticeable. Not every item was run in the game: treat the packet-level ones as verified from the code on both sides.

## clientbound-play

I compared the 129 clientbound play packet classes in the 26.3 jar with Horizon's id table and with what src/client.rs, serverui.rs, talk.rs, menus.rs, riding.rs and particles.rs handle. Packets that Penryn already handles are left out: boss bars, maps, tab list header and footer, scoreboard, titles, sounds, particles, explosions with knockback, effects, merchant offers, borders, and chat and disguised chat. The biggest gaps are the ones with no light data at all and the 26.3 swing-animation change. The next biggest are the locator bar, advancements, the recipe book and dialogs. I could not run javap, so Animate's action numbers are inferred from the constant names (WAKE_UP, CRITICAL_HIT, MAGIC_CRITICAL_HIT) rather than read as values. The 'Chat typing' item (priority 1) is only a stub: PlayerChat and DisguisedChat are in fact handled in talk.rs, and the real gap there is just ServerData and LowDiskSpaceWarning, so drop it if you want a strict list.

- **Light updates and per-block light levels (ClientboundLightUpdate, light half of LevelChunkWithLight)** (priority 10, large) — The sky and block light arrays in chunk-with-light are skipped, and ClientboundLightUpdate (id 49) is ignored. Penryn has no light levels at all: the mesher uses only fixed per-face shade. README says as much ('Penryn has no light levels yet'). *Player sees:* Caves, interiors and the night side of the world are as bright as the surface. Torches, glowstone and lava light nothing, and the brightness option can only lift the night. This is the most obvious visual difference from vanilla. *Where:* src/client.rs C_LEVEL_CHUNK_WITH_LIGHT (light data discarded), src/mesher.rs, src/world.rs

- **SwingAnimation packet (id 123) not handled; Animate packet decoded wrongly** (priority 9, small) — In 26.3 the arm swing is ClientboundSwingAnimationPacket (entityId, hand, SwingAnimation). ClientboundAnimatePacket now only has WAKE_UP, CRITICAL_HIT and MAGIC_CRITICAL_HIT. Penryn still treats Animate actions 0 and 3 as main-hand and off-hand swings, which no longer exist. It never reads id 123, and Animate's crit actions do nothing. *Player sees:* Other players and mobs never swing their arms when they attack, mine or use items. No critical or magic-crit particles appear on the hit target. Getting out of a bed is not shown for other players. *Where:* src/client.rs play::C_ANIMATE (~line 963); id 123 is absent from src/ids.rs

- **Waypoint / locator bar (ClientboundTrackedWaypoint, id 141)** (priority 6, medium) — No handler. The locator bar that replaces the experience bar when waypoints are tracked is not drawn. Player and entity waypoints are not tracked, and no icon or direction is computed. *Player sees:* On servers using the 26.x locator bar, other players' direction dots never appear, and the XP bar stays in place. *Where:* no code; 'waypoint' only appears as a tooltip attribute name in src/tooltip.rs; HUD would go in src/play.rs

- **Advancements (UpdateAdvancements, SelectAdvancementsTab) and advancement toasts** (priority 6, large) — Neither packet is handled. There are no toasts and no advancements screen. The pause menu's Advancements button is permanently disabled (src/screens.rs ~348). *Player sees:* No 'Advancement Made!' or challenge toast pops up, and no advancement screen can be opened. Servers that show progress this way give no feedback. *Where:* src/screens.rs:336-348 (disabled button); no packet handler

- **Recipe book (RecipeBookAdd, RecipeBookRemove, RecipeBookSettings, PlaceGhostRecipe)** (priority 6, large) — All four are ignored, and there is no recipe book button or panel in the inventory or crafting screens. README lists 'No recipe book'. *Player sees:* The recipe book button is missing in the inventory, crafting table and furnaces. There are no ghost-recipe overlays, no 'new recipe' toasts and no click-to-fill crafting. New players cannot look up recipes in-game. *Where:* src/menus.rs (C_UPDATE_RECIPES only keeps stonecutter recipes); src/gui.rs and src/screens.rs for the inventory

- **Stopping sounds and jukebox discs (StopSound id 121; LevelEvent 1010/1011 and the other sound-only level events)** (priority 6, medium) — StopSound is ignored. Penryn's level_event handles only 2000, 2001, 2004, 1501 and 1505, so jukebox start and stop (1010/1011), dispenser click, fire extinguish, firework, ghast, wither and dragon sounds, anvil, grindstone, book page, eye of ender, potion splash (2002/2007), dragon breath, wax on/off, scrape and sculk events (3000s) are dropped. *Player sees:* Jukebox music never plays. A server's /stopsound does nothing. Many events have no sound or particles: splash potions, ender eye break, wax on/off, anvil use, fire put out. *Where:* src/client.rs play::C_LEVEL_EVENT (~line 1029); src/particles.rs level_event (~line 1200); StopSound id 121 absent

- **Cooldown packet (ClientboundCooldown, id 22)** (priority 5, small) — Ignored. The item cooldown overlay is never drawn on hotbar or inventory slots, and use is not blocked client-side for ender pearls, shields, chorus fruit and similar. *Player sees:* No grey sweep over an ender pearl, shield or goat horn after use. Players cannot tell why the item does nothing. *Where:* no handler in src/client.rs; slot drawing in src/gui.rs or src/play.rs

- **BlockDestruction (id 5): other players' digging cracks** (priority 5, small) — Not handled. Only the local player's own crack overlay (draw_cracks in play.rs) exists. The progress stages 0-9 the server sends for other entities' mining are dropped. *Player sees:* You never see another player break a block (the cracking stages) on multiplayer servers. *Where:* src/play.rs draw_cracks (~line 2353) only draws the local hit; add a per-entity map in src/client.rs

- **GameEvent: most events other than 1, 2, 3, 7, 8 and 11** (priority 5, small) — Event 4 (win game, credits), 6 (arrow hit player: the 'ding' sound), 9 (pufferfish sting), 10 (elder guardian curse: the guardian image and sound), 5 (demo messages), 12 (limited crafting), 13 (start waiting for level chunks) and 0 (no respawn block available message) are ignored. *Player sees:* No arrow-hit ding. No guardian curse effect. No 'Your home bed was missing or obstructed' message. Ending the game does not show credits. *Where:* src/client.rs play::C_GAME_EVENT (~line 673)

- **PlayerRotation (id 74) and PlayerLookAt (id 72)** (priority 5, small) — Neither is handled. A server that rotates the player (/rotate, /tp ... facing, /execute rotated, look-at) is ignored, because only PlayerPosition's yaw and pitch fields are applied. *Player sees:* /tp facing and /rotate leave the camera looking where it was. Plugins that aim the player's view have no effect. *Where:* src/client.rs near C_PLAYER_POSITION (~line 505); ids missing from src/ids.rs

- **ShowDialog and ClearDialog (ids 143, 142)** (priority 5, large) — Not handled, and src/text.rs notes show_dialog click events do nothing. 26.x server dialogs (notice, confirmation, multi-action and server-link lists) never open. *Player sees:* Servers using the 26.x dialog API for rules, menus or confirmations show nothing, and players cannot reach those options. *Where:* no handler; src/text.rs:170 explicitly ignores show_dialog

- **SetEntityLink (id 102): leads and leashes** (priority 4, medium) — Not handled. Leash links between a mob and its holder, or a fence knot, are never drawn. *Player sees:* Leashed horses, cows, wolves and boats show no lead rope. *Where:* no handler; would go in src/entities.rs or src/mobs.rs

- **SetDefaultSpawnPosition (id 99) and compass/lodestone targets** (priority 4, medium) — Ignored. The world spawn point is not stored. Compass, recovery compass and lodestone needles have no target (and no death-location tracking). *Player sees:* Compasses in the inventory and hand always point the same way, rather than at spawn or the lodestone. *Where:* no handler; item models in src/itemmodels.rs

- **MoveMinecartAlongTrack (id 56)** (priority 4, medium) — Not handled. The experimental-minecart-improvements packet that sends interpolated steps for each minecart is dropped. Only the old teleport/position packets move minecarts. *Player sees:* On servers with the new minecart behaviour, carts jump or stay still, and riding one is jerky or wrong. *Where:* src/riding.rs and src/entities.rs (minecarts are 'the server's to move'); no handler for id 56

- **PlayerPosition delta movement ignored** (priority 3, small) — The three delta-movement doubles (_d) and their relative-flag bits (32/64/128 and rotate-delta) are read and thrown away. Only vy is zeroed, and x and z velocity are not set or kept. *Player sees:* Teleports that carry momentum (ender pearl landing, some server launchers, relative velocity teleports) stop the player dead, where vanilla keeps or sets the velocity. *Where:* src/client.rs play::C_PLAYER_POSITION (~line 509, `let _d = ...`; `pl.vy = 0.0`)

- **Chunk view center and radius (SetChunkCacheCenter id 96, SetChunkCacheRadius id 97, SetSimulationDistance id 113)** (priority 3, small) — All three are ignored. Penryn only drops chunks when the server sends ForgetLevelChunk. It never applies the server's view radius or centre to its own rendering or loading, and has no cache-radius limit. *Player sees:* On servers whose view distance is lower than the client setting, the HUD and loading screen can wait for chunks that never come. Wrongly-centred chunks are not culled after fast teleports. *Where:* src/client.rs handle() (no case); src/world.rs forget and loaded

- **AwardStats (id 3) and the Statistics screen** (priority 3, medium) — Not handled. There is no statistics screen or button. The pause menu's Statistics button is disabled like Advancements. *Player sees:* No stats screen, so blocks mined, distance walked and kills cannot be viewed. *Where:* src/screens.rs:336-350 (disabled buttons)

- **BlockChangedAck (id 4) and client-side prediction** (priority 3, medium) — Id 4 is in ids.rs but never handled. Penryn sends sequence numbers but keeps no prediction, so there is no rollback. *Player sees:* Block placing and breaking look laggy on slow connections, because the block only appears once the server's BlockUpdate arrives. There is no immediate local preview. *Where:* src/client.rs place() and dig() (sequence counter only; `placing` is a hint)

- **ChunksBiomes (id 13)** (priority 2, small) — Ignored. Server-sent biome updates for already-loaded chunks (for example after /fillbiome) are not applied. Biome tints and sky colours stay as first loaded. *Player sees:* After /fillbiome, grass, water and foliage colours do not change until the chunk reloads. *Where:* src/world.rs biome storage; no handler in src/client.rs

- **ProjectilePower (id 138), PlayerCombat Enter/End (67, 68) and ChangeDifficulty (10)** (priority 2, small) — Ignored. Projectile power (the acceleration for fireballs and wind charges) is not applied to the entity. Difficulty is not stored, and there is no Difficulty line in F3 or the options screen's lock state. *Player sees:* Fireballs and similar projectiles can look off between server updates. The options screen shows no difficulty. *Where:* src/client.rs; src/options.rs (no difficulty state)

- **CustomChatCompletions (id 23) and TagQuery (126)** (priority 2, small) — Ignored. Server-sent custom chat completions (add, remove, set) never reach the chat box suggestions, which only use the command tree. *Player sees:* Plugin-provided tab completions of player names or custom words do not show in chat. *Where:* src/talk.rs and src/commands.rs (suggestions come from C_COMMANDS only)

- **Debug packets (DebugBlockValue, DebugChunkValue, DebugEntityValue, DebugEvent, DebugSample) and TickingState/TickingStep** (priority 2, small) — All ignored. There is no debug overlay data for the F3+ pie charts, and no server tick rate: the game is not frozen client-side by /tick freeze and there is no TPS in F3. *Player sees:* /tick freeze and /tick rate are not mirrored. Entity animations and particles keep running when the server freezes. F3 has no server tick graph. *Where:* src/client.rs tick(); src/play.rs F3 screen

- **Chat typing: PlayerChat and DisguisedChat** (priority 1, small) — Both are handled in talk.rs. Not missing, but the 'LowDiskSpaceWarning' (id 51) and 'ServerData' (id 88) packets are ignored. The server list MOTD and icon are not updated in-game, and there is no low-disk-space toast. *Player sees:* Minor: no in-game server icon or MOTD update. No chat-banner state for enforced secure chat beyond what talk.rs does. *Where:* src/client.rs handle (no case for 88 or 51)

## serverbound-play

Of 75 Serverbound classes, Penryn sends about 50. The missing ones are player-visible features rather than plumbing. Chat session/ack/signed commands, container clicks, trade, beacon, anvil rename, book edit, sign update, boat paddle, vehicle move, resource pack, cookies, known packs, code of conduct and the login/config handshake are all present. I did not count the status, handshake and server-driven packets. Biggest gaps are the recipe book (PlaceRecipe, RecipeBookSeen, RecipeBookChangeSettings), advancements (SeenAdvancements), spectator teleport and PickItemFromEntity. Op and admin tools (command and structure blocks, jigsaw, test blocks, difficulty, gamerules, gamemode switcher, NBT queries) and custom click actions, debug subscriptions and ping requests are absent too. The README's Not done yet list confirms the recipe book and spectator menu. Bundle selection, difficulty, advancements, tag queries and command blocks come from absent sender code in a grep, not reading every screen. I did not decompile the jar to check packet field layouts.

- **Recipe placement and recipe book (ServerboundPlaceRecipe, RecipeBookSeenRecipe, RecipeBookChangeSettings)** (priority 9, large) — No recipe book at all (README confirms). Penryn never sends PlaceRecipe (shift-click ghost recipe fill into crafting grid/furnace), RecipeBookSeenRecipe or RecipeBookChangeSettings. The recipe-book toggle button and recipe-unlock toasts are absent. *Player sees:* Cannot one-click fill crafting table, furnace, smoker or blast furnace from the recipe book; survival crafting must be done by hand-placing every ingredient. *Where:* src/ids.rs (no ids), src/menus.rs (crafting/furnace screens)

- **Advancements screen (ServerboundSeenAdvancements)** (priority 7, large) — Never sends SeenAdvancements (open tab / close screen). The advancements button in the pause menu is a disabled stub (screens.rs: .off()); the L keybind is registered but has no screen. *Player sees:* No advancements screen. Opening it is how a client tells the server which tab it has seen, so server-side toast and tab behaviour never updates. *Where:* src/screens.rs ~line 348, src/keybinds.rs line 98

- **Spectator menu and teleport (ServerboundTeleportToEntity, ServerboundSpectatorAction)** (priority 7, medium) — Neither packet is sent. README says the spectator hotbar menu (teleporting to players) is not done. A spectator also cannot teleport by the player-list or the spectator menu. *Player sees:* In spectator mode you cannot jump to another player or cycle through them; you can only fly freely. *Where:* src/gamemode.rs, src/play.rs, src/ids.rs

- **Pick item from entity (ServerboundPickItemFromEntity)** (priority 6, small) — Only S_PICK_ITEM_FROM_BLOCK (36) is defined and sent (play.rs:416); the entity variant is not in ids.rs and middle-clicking an entity does nothing. Vanilla sends it for spawn eggs, boats, minecarts, armor stands, paintings, item frames, etc., and for creative-mode pick-entity. *Player sees:* Middle-click on a mob, boat, minecart, painting or item frame does not pick the matching item/spawn egg. *Where:* src/play.rs around line 416, src/ids.rs

- **Command block editing (ServerboundSetCommandBlock, ServerboundSetCommandMinecart)** (priority 6, medium) — No command block or command block minecart screen and no packet. Penryn has no handler for the open-screen request for command blocks, nor for sending the command, mode (impulse/chain/repeat), conditional and always-active flags. *Player sees:* Operators in creative cannot edit command blocks; right-clicking one does nothing. *Where:* src/menus.rs, src/screens.rs, src/client.rs (open-screen-for-block-entity handling)

- **Bundle item selection (ServerboundSelectBundleItem)** (priority 5, small) — Penryn does not send SelectBundleItem when the player scrolls/hovers over a bundle's contents in a container (vanilla highlights an entry and tells the server which index is selected so the bundle tooltip and the next take-out pick that stack). The grep for bundle logic in Penryn finds no sender. *Player sees:* Bundles cannot choose which stack inside to take out; the highlighted item and take-out order differ from vanilla. *Where:* src/menus.rs (container click / mouse-wheel handling), src/tooltip.rs, src/ids.rs

- **Structure block, jigsaw and test block editing (SetStructureBlock, SetJigsawBlock, JigsawGenerate, SetTestBlock, TestInstanceBlockAction)** (priority 4, large) — None of these 5 packets exists in Penryn; the corresponding editor screens are absent (structure save/load/corner/data mode, jigsaw pool/target/name and Generate button, test blocks). *Player sees:* Builders/ops cannot configure structure, jigsaw or test blocks; useful for creative building servers. *Where:* src/menus.rs, src/screens.rs (no code present)

- **Change difficulty / lock difficulty (ServerboundChangeDifficulty, ServerboundLockDifficulty)** (priority 4, small) — Options screen has no Difficulty button (no 'difficulty' string anywhere in the sources), so neither packet is sent. Vanilla shows the difficulty cycle button and lock button in the Options screen (and lock-padlock) when the player is op or in singleplayer. *Player sees:* Operators cannot change or lock the server difficulty from the pause/options menu; they must use /difficulty. *Where:* src/options.rs, src/screens.rs (pause screen), src/ids.rs

- **Change game mode via switcher (ServerboundChangeGameMode)** (priority 4, small) — No S_CHANGE_GAME_MODE id or sender; the F3+F4 game mode switcher (and the one-click switch from the debug screen) is absent. Only the server's gamemode-change packet is handled in gamemode.rs. *Player sees:* Operators cannot switch creative/survival/spectator/adventure with F3+F4; they must type /gamemode. *Where:* src/gamemode.rs, src/keybinds.rs, src/ids.rs

- **Custom click actions (ServerboundCustomClickAction)** (priority 4, medium) — Penryn defines no handler or sender for dialog or text-component custom_click actions (dialogs on 26.x servers); clicking a chat component with custom action does nothing. *Player sees:* Server-defined clickable chat or dialog buttons that send a custom payload do nothing. *Where:* src/chatui.rs, src/talk.rs, src/ids.rs (play and config)

- **Game rule editor (ServerboundSetGameRule)** (priority 3, medium) — Packet new in 26.x for the op game-rule editing screen. Penryn has no id or screen for it. *Player sees:* Operators cannot edit game rules from a screen, only via /gamerule. *Where:* src/screens.rs, src/ids.rs

- **Block / entity NBT query (ServerboundBlockEntityTagQuery, ServerboundEntityTagQuery)** (priority 3, small) — Neither packet is sent. Vanilla uses them for F3+I (copy block/entity data to the clipboard) and the debug 'looking at' NBT display. *Player sees:* F3+I does not copy block or entity data; creative/op debugging tool missing. *Where:* src/keybinds.rs, src/ids.rs

- **Debug subscription request (ServerboundDebugSubscriptionRequest)** (priority 2, medium) — Penryn never subscribes to server debug info (tick chart, pathfinding, entity brains, chunk debug etc.) that F3 sub-screens request. *Player sees:* F3 debug overlays that need server data (tick time, etc.) never show server-side values. *Where:* src/ids.rs, src/client.rs

- **Ping request (ServerboundPingRequest)** (priority 2, small) — Play-state PingRequest id is absent; vanilla uses it with the F3 ping chart / network latency graph. *Player sees:* F3+3 (ping chart) cannot show round-trip latency. *Where:* src/ids.rs, src/client.rs

## screens

Checked against the 26.3 jar's screen classes, en_us.json and Penryn's src/. Penryn already has the title screen, the multiplayer list, direct connect, the server list's edit screen, the pause menu, most Options sub-screens (including Resource Packs), the container menus, books, sign edit, the creative inventory, the death screen, the server links screen, the resource pack confirm and the connect and disconnect screens. What is missing falls into two groups. The first is pause-menu buttons that are drawn but greyed or not drawn: Advancements, Statistics, World Options and the icon row. They have no screen behind them, and the packets that would feed them (advancements, award stats, recipes, show dialog) have no ids in src/ids.rs and no handler in src/client.rs. The second is whole screens vanilla has and Penryn does not: language, telemetry, credits, recipe book, social interactions, the spectator and game mode menus, server dialogs, and the operator block editors.

- **Advancements screen and toasts (AdvancementsScreen)** (priority 8, large) — The pause menu's Advancements button is greyed (.off() in screens.rs pause_buttons), the L key (key.advancements) is bound in keybinds.rs but opens nothing, and there is no handler for the server's advancements update packet. There is no tab strip, tree view or advancement toast. *Player sees:* Players cannot view their advancements or progress, and they never see 'Advancement Made!' toasts, which every survival server triggers. *Where:* src/screens.rs pause_buttons, src/ids.rs and src/client.rs (packet), a new screen module

- **Recipe book (RecipeBookComponent, in the inventory, crafting table, furnaces, blast furnace and smoker)** (priority 8, large) — The recipe book button and panel are not drawn in the survival inventory, crafting table, furnace, blast furnace or smoker screens. The README lists this under 'Not done yet'. There is no handling of the recipe book add, remove and settings packets, and no ghost recipe (place-recipe) request. *Player sees:* Survival players cannot click a recipe to fill the crafting grid. The green book button that vanilla shows beside the grid is absent. *Where:* src/screens.rs and src/menus.rs (the crafting, furnace and inventory windows), src/client.rs

- **Server dialogs (net/minecraft/client/gui/screens/dialog/*: SimpleDialog, MultiButtonDialog, ServerLinksDialog, DialogList, WaitingForResponse)** (priority 7, large) — The packets that show and clear a dialog (usable in play and in configuration) are not handled. There are no dialog screens with text, input, boolean and number-range widgets and action buttons. Only the Server Links screen exists, and it is Penryn's own version, not the DialogScreen family. *Player sees:* Servers that use the dialog API for rules, forms, confirmations or a custom pause menu show nothing, so players cannot respond and the server may be waiting on them. *Where:* src/ids.rs, src/client.rs (the configuration and play packet handlers), src/serverhud.rs

- **Statistics screen (StatsScreen)** (priority 6, medium) — The pause menu's Statistics button is greyed. Penryn sends no client command to request stats and has no handler for the award-stats packet. There is no General, Items or Mobs tab. *Player sees:* The Statistics button does nothing, and no stat tables can be shown. *Where:* src/screens.rs pause_buttons (the .off() Statistics button), src/client.rs

- **Sleeping: Leave Bed button (InBedChatScreen) and in-bed state** (priority 6, small) — There is no handler for sleeping. Vanilla shows 'Leave Bed' (multiplayer.stopSleeping) in a chat screen while in bed and sends the stop-sleeping command. Penryn has no sleep state, no leave-bed button and no dimmed view in bed. *Player sees:* After a player clicks a bed, nothing tells them how to get up, and they are not shown lying in bed. Esc and chat do not give vanilla's Leave Bed button. *Where:* src/play.rs (screen state), src/screens.rs, src/chatui.rs

- **Social Interactions screen (SocialInteractionsScreen, P key)** (priority 5, medium) — The key is bound in keybinds.rs but opens nothing. There are no All, Hidden or Blocked tabs, no player search, and no hide/show or report buttons. The pause menu's player reporting icon is also absent. *Player sees:* Players cannot hide or mute another player's chat, or see the online player list as vanilla's panel, from the keyboard. *Where:* src/keybinds.rs (Social), src/chatui.rs for the hidden-player filter, a new screen

- **Language screen (LanguageSelectScreen) behind Options > Language...** (priority 5, medium) — The button is drawn greyed (W::Off("options.language") in options.rs). The language list, Done and the 'forceUnicodeFont' toggle are missing, and the language is not stored in options.txt. *Player sees:* Players cannot change the game language. The button stays greyed, so the whole UI stays in English. *Where:* src/options.rs Page::Main grid and W::Off, src/lang.rs (loads the game's lang)

- **Death screen button: 'Title Screen' and its confirmation (DeathScreen / TitleConfirmScreen)** (priority 4, small) — The second button is labelled with menu.disconnect ('Disconnect'). Vanilla labels it deathScreen.titleScreen ('Title Screen'), and in non-hardcore asks 'Are you sure you want to quit?' (deathScreen.quit.confirm) with a Title Screen / Respawn choice. *Player sees:* A visible wrong label on a screen every player sees, and the one-click leave has no confirmation. *Where:* src/screens.rs death_buttons (line 369) and src/serverhud.rs death_buttons

- **Game mode switcher (GameModeSwitcherScreen, F3+F4) and F3+F6 debug options (DebugOptionsScreen)** (priority 4, small) — There is no popup of the four game mode icons that F3+F4 opens, and no handling of its selection (it sends a game-mode command). F3 combinations in play.rs only cover F3 and F3+A. The F3+F6 debug options screen is also absent. *Player sees:* Operators and creative players have no hotkey to change game mode. Creative servers with permissions cannot use vanilla's F3+F4 menu. *Where:* src/play.rs key handling near K_F3 (lines 1319-1321), src/gamemode.rs

- **Spectator hotbar menu (SpectatorGui: teleport to player, team teleport)** (priority 4, medium) — The README already notes it is not done. In spectator mode, vanilla shows a menu on the hotbar with Teleport to Player and Teleport to Team. Penryn only has the fly-through camera and no menu. *Player sees:* Spectators cannot jump to other players, and the scroll wheel does not cycle spectator speed or open the menu. *Where:* src/gamemode.rs, src/play.rs hotbar and scroll handling

- **Operator editor screens: command block, minecart command block, structure block, jigsaw, test block (CommandBlockEditScreen, StructureBlockEditScreen, JigsawBlockEditScreen, TestBlockEditScreen)** (priority 4, large) — There are no screens for editing these blocks. Penryn has the sign editor (OpenSignEditor) and books, but nothing sends the update-command-block, update-structure-block or update-jigsaw packets. *Player sees:* Operators and creative builders cannot edit command blocks or structure blocks on a server. Right clicking them does nothing. *Where:* src/ids.rs (no ids), src/client.rs C_OPEN_SCREEN and block-entity handlers, new screen

- **Telemetry (TelemetryInfoScreen) and Credits (CreditsAndAttributionScreen) under Options** (priority 3, small) — Both buttons are drawn greyed (W::Off in options.rs). Neither screen exists: the telemetry description and Open Data Sharing buttons, and the Credits and Attribution screen with its Credits, Attribution and Licenses buttons. *Player sees:* Two greyed-out entries in the main Options grid. *Where:* src/options.rs Page::Main grid

- **Pause menu icon row and feedback/report buttons** (priority 3, small) — The comment in pause_buttons says the icon row (feedback, bugs, friends, reporting) 'keeps its place but is not drawn'. Vanilla's PauseScreen draws Give Feedback, Report Bugs (both open links) and Player Reporting. The World Options... button is also drawn greyed, though it only matters in singleplayer. *Player sees:* The pause menu shows empty rows where vanilla has the Feedback and Report Bugs link buttons. *Where:* src/screens.rs pause_buttons and draw_pause (line 334 onward)

- **Reporting screens (ReportPlayerScreen, ChatSelectionScreen, ChatReportScreen, ReportReasonSelectionScreen, SkinReport, NameReport)** (priority 2, large) — There is no report path. Chat messages carry no 'report' button in the chat selection, and the Social Interactions report buttons do not exist. *Player sees:* Players cannot report chat messages, names or skins from the game. *Where:* src/chatui.rs, a new report module that would also need the relay's report service

- **Singleplayer, Realms and World select screens (SelectWorldScreen, CreateWorldScreen, EditWorldScreen, RealmsMainScreen)** (priority 2, large) — The Singleplayer and Realms buttons are drawn greyed on the title screen, and Penryn has no integrated server. The Create World, Select World and Edit World screens do not exist. Multiplayer-side screens that need no server (ServerReconfigScreen, ManageServer's Resource Packs setting, Safety and Warning screens) are also absent apart from the ones listed in the README. *Player sees:* Two permanently greyed main-menu buttons. Players can only join servers. *Where:* src/title.rs (the main buttons around line 415)

- **Friends overlay (FriendsOverlay)** (priority 1, large) — There is no friends list, friends overlay or invite handling. The README lists friends under screens not done. *Player sees:* No friends button or overlay in the title and pause menus. *Where:* src/title.rs and src/screens.rs

## gameplay

Read-only sweep of the gameplay area against 26.3.jar (Options key names, DebugScreenEntries, KeyMapping, packet classes) and Penryn's play.rs, screens.rs (hud, debug), hand.rs, client.rs, keybinds.rs and options.rs. The list holds only gaps I checked on both sides. The README's "no third-person view" line is stale: perspective and the player's own model exist, so I did not list it. The 9 bindings in key.* with no Penryn counterpart are also absent from the list: debug.* combos other than A, quickActions, spectatorHotbar and similar.

## packs-fonts

Read-only sweep of tools/make_assets.py and src/packs.rs against the 26.3 jar and its asset index. Pack overlays, filters, sounds, reference fonts, bitmap and space fonts, and the first frame of animations are handled. The font gaps are the biggest: the unihex fonts (unifont.zip, unifont_pua, unifont_jp) are never baked, so non-Latin text and symbols draw as '?'. ttf and legacy_unicode providers are skipped, and the uniform, alt and illageralt fonts use default glyphs. Textures are the other big gap: animations stay on frame 0, atlases/*.json is unread, and every block, item and particle texture is scaled to 16x16, so HD packs lose detail. Core and post shaders are unsupported, and GUI sprites for toasts, advancements, the recipe book and dialogs are not packaged. Nine-slice scaling reads only the left border, other languages are not loaded, and pack icons are not drawn. I did not edit or build anything. Items 13 (pack.mcmeta description components) and 14 (compass and clock dynamic states) are the least verified; I did not read the code that draws the pack list descriptions or the items definitions for compass and clock.

- **Unihex font (unifont) missing** (priority 9, large) — The jar's include/unifont.json is empty; the real unifont providers are asset objects (minecraft/font/unifont.zip, unifont_jp.zip, unifont_pua.zip with their include json) in the installed asset index. make_assets.py build_font() handles only 'bitmap' and 'space' providers (line ~1979-1984) and skips unihex entirely, so the only glyph pages are ascii, accented and nonlatin_european. *Player sees:* Any character outside Latin/Greek/Cyrillic (CJK, Arabic, Hebrew, Thai, emoji and symbols like U+2726, box-drawing, arrows) in chat, signs, books, anvil names and server MOTDs draws as '?' (gui.rs falls back to the '?' glyph). Servers and players using non-Latin text are unreadable. *Where:* tools/make_assets.py build_font/font_refs (~1956-2035); src/gui.rs glyph lookup ~623/681/907; gui.bin glyph table

- **Animated textures show only the first frame** (priority 9, large) — first_frame() in make_assets.py (line 390) takes frames[0] of the .mcmeta animation and bakes it into the 16x16 tile; no frame strip, frametime, interpolate or frame order is kept, and the renderer has no texture-animation path (no TexSubImage or per-frame UV offset). *Player sees:* Water, lava, fire, nether portal, magma, sea lantern, prismarine, kelp, seagrass, soul fire, lit furnaces' fire, command blocks, sculk, crimson/warped stems and every animated pack texture (also item and particle sprites, GUI sprites) are frozen still images. *Where:* tools/make_assets.py first_frame/texture() 1320-1345; atlas.bin layout; src/render.rs atlas upload

- **High-resolution pack textures are downscaled to 16x16** (priority 8, large) — texture() calls tile_of(img), which scales every block texture whole to a 16x16 tile (nearest); the atlas is a fixed 16-pixel-tile grid (64 tiles a row). Pack atlas sizes, mipmap levels and per-sprite sizes are not supported. Only the 64x64 block-entity rows differ. *Player sees:* 32x, 64x, 128x and 256x resource packs lose all their detail on blocks, items and particles; they look like 16x versions, so a player who installs a HD pack sees no improvement. *Where:* tools/make_assets.py tile_of/texture() ~523 and 1320; atlas.bin 'PNA2'; src/mesher.rs UVs

- **Fonts: ttf provider ignored** (priority 6, large) — Provider type 'ttf' (file, size, oversample, shift, skip) is not handled by build_font; only bitmap, space and reference are. There is no TrueType rasteriser (README confirms). *Player sees:* Packs that ship a custom font (ttf-based chat or UI fonts, Minecraft-style replacements) fall back to the default bitmap font; their glyphs for characters outside the bitmap pages show as '?'. *Where:* tools/make_assets.py build_font ~1979; would need a baked glyph atlas since Penryn is no_std

- **Equipment and item-model textures higher than 16x frozen/downscaled in GUI icons** (priority 6, large) — Item icons are built from textures drawn into the 16x16 block atlas (items.bin); item model layers from packs use the same tile_of() downscale and no animated item (compass, clock, recovery compass, crossbow pull) range_dispatch states beyond a static frame. *Player sees:* Items in the hotbar and inventory from HD packs look blurry 16x, and compasses and clocks stay fixed at their first sprite instead of rotating or showing the time. *Where:* tools/make_assets.py items section 1574-1766; src/itemmodels.rs

- **GUI sprites for toast, advancements, recipe book, dialog, statistics, player list and others not packaged** (priority 5, large) — The sprite loader takes only gui/sprites folders hud/, widget/, tooltip/, container/*, plus a hand list for boss_bar, icon, spectator, server list; folders toast (12), advancements (33), recipe_book (29), dialog (3), statistics (9), player_list (3), notification (6), social_interactions (8), pending_invite, world_list, popup and gamemode_switcher are never added, so pack replacements for them cannot show and the screens built on them do not exist. *Player sees:* No advancement/recipe/system toasts, no advancements, recipe book or statistics screens, no server-sent dialog screens drawn with sprites; pack-skinned versions of those are never visible. *Where:* tools/make_assets.py add_sprite loop 1911-1921 and make_containers/make_menu lists; no toast code in src

- **legacy_unicode provider ignored** (priority 4, medium) — build_font skips type 'legacy_unicode' (sizes file plus template glyph_XX.png pages) used by older and some custom packs for the unicode_page_ fonts. *Player sees:* Packs relying on legacy_unicode pages (glyph_sizes.bin) lose their non-ASCII glyphs: '?' instead. *Where:* tools/make_assets.py build_font ~1984

- **atlases/*.json source definitions not read** (priority 4, large) — No code reads assets/*/atlases/*.json (blocks, items, gui, particles, paintings, etc.): the 'directory', 'single', 'filter', 'unstitch' and 'paletted_permutations' source types. Textures are located by hard-coded paths and the block/item models that reference them. *Player sees:* Packs that add textures through an atlas json (custom directories, unstitched sprites, palette-permuted textures such as trims or colour-swapped sprites, or filtered-out sprites) get the magenta missing texture or the vanilla one instead. Armor trims are not recoloured by palette permutation either. *Where:* tools/make_assets.py texture() and make_entities; no atlases handling

- **Pack icon (pack.png) not drawn in the selection screen** (priority 4, medium) — packs.rs line ~1119 leaves a blank icon place; make_assets does not export pack.png. Vanilla draws each pack's pack.png (and the vanilla default) with the unknown_pack texture fallback. *Player sees:* The resource pack list shows rows without icons (plus no 'unknown_pack' placeholder), so packs are harder to tell apart. *Where:* src/packs.rs ~1119, 1172-1220 draw_entry; gui sprite unknown_pack

- **Core and post shaders / post effects not supported** (priority 4, large) — assets/minecraft/shaders/core/*.vsh/fsh and post_effect/*.json (blur, creeper, spider, invert, entity_outline) are ignored (README: core shaders ignored, OpenGL 1.5). No post-effect pipeline. *Player sees:* Shader packs and pack-modified core shaders (custom entity tints, fog, custom rendertypes, CIT-style tricks) have no effect; the spider and creeper spectator vision, glowing entity outline and the menu background blur are missing, so menus have no blur behind them. *Where:* no shader path in src/render.rs; menu blur missing in src/screens.rs/gui.rs

- **Pack languages other than en_us not loaded** (priority 4, medium) — Only lang/en_us.json is read, merged over pack files (make_assets.py line ~2113). Other lang/*.json and the language setting are not baked, and the 'Language' screen is absent; the jar's lang folder lists none other than en_us anyway (other languages come from the asset objects). *Player sees:* The game is English only, even with a pack that adds or overrides another language, and with Options > Language set to another language the setting does nothing. *Where:* tools/make_assets.py 2113-2121; src/lang.rs; src/options.rs

- **GUI sprite scaling: only nine_slice with one border value** (priority 4, medium) — add_sprite() reads gui.scaling only when type==nine_slice and uses just the 'left' border (or the int) for all four sides. Types 'tile' and 'stretch', per-side borders (left/top/right/bottom), nine_slice 'stretch_inner', and tiled nine-slice are not recorded. *Player sees:* Pack buttons, tooltips, backgrounds or hotbar sprites with asymmetric borders, tiled middles or 'tile' scaling are stretched or corrupted instead of drawn as the pack author intended. *Where:* tools/make_assets.py 1898-1910; gui.bin sprite record (1 byte border); src/gui.rs nine-slice draw

- **Uniform, alt (Standard Galactic) and illageralt fonts drawn with default glyphs** (priority 3, small) — Fonts minecraft:uniform, minecraft:alt and minecraft:illageralt are never built into the extra_fonts table (build_font runs for minecraft:default only and extra_fonts excludes alt/illageralt/default; uniform is also not excluded but is only built with packs). The alt glyphs exist only in containers.bin for the enchanting table. *Player sees:* Chat or signs that use {"font":"minecraft:alt"} or "minecraft:illageralt" (and the uniform font option) show normal Latin text instead of the enchanting-table or illager runes; the option 'Force Unicode Font' has no effect (README lists this). *Where:* tools/make_assets.py ~2013-2030 extra_fonts; src/text.rs:200 and 386 font id mapping; options force-unicode

- **Font provider 'filter' and 'skip' not honoured beyond uniform:true on references** (priority 2, small) — Only reference providers with filter.uniform==true are dropped (line 1967). A filter on bitmap/space/ttf/unihex providers (filter.uniform / filter.jp) is not evaluated, and 'chars' entries equal to the space or NUL are handled only as cp==0; bitmap 'height' with fractional scale is truncated by int(). Space providers' advances are only taken from the first match, with no 'skip' list. *Player sees:* Packs that use filtered providers (uniform-only or JP-only glyph sets) get both sets mixed, so a glyph can come from the wrong provider and look different from vanilla; rarely noticed. *Where:* tools/make_assets.py font_refs/build_font 1962-1990

- **Overlay/filter handling also needs sounds, fonts and lang through the same pack stack** (priority 2, small) — Pack stack (overlays, filter block) is implemented in make_assets.py for assets via the stack, but pack.mcmeta 'language' declarations (a pack's own language names/regions) and 'features'/'supported_formats' variations outside this version's overlay rules, and the resource pack 'pack.mcmeta' text description in the list use plain text only. *Player sees:* Pack descriptions with JSON text components (colours, formatting) in pack.mcmeta show plain or raw text in the selection screen. *Where:* src/packs.rs draw_entry ~1179-1210
